# Accessibility checklist

Run this before considering a Tailwind UI complete. Classes do not replace semantics.

## Structure

- [ ] Headings in order (`h1` → `h2` → `h3`); do not skip levels for `text-xl`
- [ ] One `h1` per page/view
- [ ] Lists are `ul`/`ol`; navigation is `nav`; landmark regions have labels if repeated
- [ ] Buttons are `<button type="button">` (or `submit`). Links are `<a href>`. Never `div onClick` for primary actions
- [ ] Icon-only controls have an accessible name (`aria-label`, `sr-only` text, or `title` **plus** `aria-label`)

## Contrast and color

- [ ] Body text ≥ 4.5:1 against its actual background (including overlays)
- [ ] Large text / icons that convey meaning ≥ 3:1
- [ ] Status is not color-only (text, icon, or pattern with the color)
- [ ] Placeholder is not the only instruction; associate a visible `<label>`
- [ ] Brand / teal / mint used as text was checked — light brand fills often fail as foreground

## Focus

- [ ] No `outline-none` without a `focus-visible:` ring (or equivalent)
- [ ] Focus ring contrast ≥ 3:1; offset so it is not swallowed by the border
- [ ] Tab order matches visual order; no positive `tabindex`
- [ ] Modals trap focus and restore it on close; `Escape` dismisses
- [ ] Skip link or equivalent if the chrome is tall (sidebar + top bar)

Typical ring:

```html
class="focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background"
```

## Forms

- [ ] Every input has a label (`htmlFor` / `id`, or wrapping `label`)
- [ ] Errors are text, linked with `aria-describedby`, not color-only borders
- [ ] `autocomplete` on common fields (email, name, current-password)
- [ ] Required fields indicated in text, not only a red asterisk in a low-contrast color
- [ ] Disabled fields are not the only way to hide required info; prefer `readonly` when the value must be read

## Motion and media

- [ ] Decorative animation respects `motion-reduce:` / `prefers-reduced-motion`
- [ ] Auto-playing motion can be stopped; no infinite decorative bounce on CTAs
- [ ] Images have `alt` (empty if decorative)
- [ ] SVGs that are informative have `role="img"` + title, or are inside a named button
- [ ] Contrast of text over images uses a scrim (`bg-black/50`) or solid plate, not hope

## Touch and target size

- [ ] Interactive targets ≥ 24px (prefer 44px on primary mobile actions)
- [ ] Nearby controls have gap (`gap-2`+) so they are hard to mis-tap
- [ ] Hover-only content is available on keyboard/touch (click, focus, or always-visible)

## Dark mode

- [ ] Light and dark both meet contrast; do not “fix” only light
- [ ] Hairline borders still visible (`border-border`, not `border-white/5` on `bg-zinc-950` if 1.2:1)
- [ ] Focus ring visible on both canvases (`ring-offset-background`)

## Content

- [ ] No emoji as status, tab labels, or button content (use SVG icons)
- [ ] Visible text is in the DOM (not only CSS `content:`)
- [ ] `sr-only` used for extra context, not as a dumping ground that duplicates noisy strings

## Quick fail patterns (do not ship)

```html
<!-- fail: clickable div, no keyboard, no name -->
<div class="cursor-pointer" onclick="...">Edit</div>

<!-- fail: outline removed, no ring -->
<button class="outline-none">Save</button>

<!-- fail: color-only error -->
<input class="border-red-500" />

<!-- fail: low-contrast muted body copy as the actual label -->
<p class="text-zinc-400 text-xs">Email</p>
```
